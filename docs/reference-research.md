# 棒人間RPG / Stickman RPG 調査

調査日: 2026-11-12。対象開発者は Goro Sato。**最新のユーザー指定は「マップと1人パーティはIを軸、システムはII・IIIの進化も参考にする」。** 類似名の Stick RPG、Epic Stickman、Stick Ranger 等は対象外。

## 調査の限界

実機プレイによる検証ではない。作者公式サイトからシリーズのApp Storeリンクを確認したが、現在のAppleページは取得できなかった。以下は公開されたアプリ説明の保存・転載ページ、当時のプレイ記事、公開スクリーンショットに基づく。前提スキルの接続関係を含む完全なスキルツリー、全スキルの数値、計算式は確認できていない。未確認情報を原作仕様として扱わない。

## 公開アプリ説明で確認した仕様

初代・II・IIIで共通して確認できる基本構造:

- 戦闘報酬はコインとXP。
- **XPを消費して能力を伸ばす、またはスキルを習得する。育成先が同じ資源を取り合う。**
- スキルの習得と戦闘へのセットは別。セットするスキルは最大4つ。
- 初代・IIの英語説明には同じスキルの複数スロットへのセットが可能とある。
- コインで武器・防具・アイテムを購入し、購入後に装備する。
- アイテムの戦闘用装備枠も最大4つ。武器・防具を含めた総数4枠、という意味にはしない。
- クリア済みの敵への再挑戦により資源を稼げる。

IIIの日本語説明には能力が5パラメータであること、マップ内の連続戦闘、セット終了ごとの装備・スキル変更、HPを消費する即時オート戦闘も記されている。

出典（アプリ説明の転載・保存。作者公式サイトそのものではない）:

- [初代 / AppStorio](https://stickman-rpg.appstor.io/)
- [II / AppStorio](https://stickman-rpg-ii.appstor.io/)
- [III 日本語 / AppStorio](https://stickman-rpg-iii.appstor.io/ja)

## プレイ記事で補足できること

[.Appsによる初代のプレイ記事](https://dotapps.jp/static/articles/qqfs7fmfjbn4pnqf)は、撮影画像付きで次を説明している。アプリ本体を今回実行して追認した情報ではない。

- コマンドは通常攻撃・スキル・アイテム・逃走。
- スキルにはSP消費とクールダウンがある。
- パラメータはHP・SP・ATK・DEF・AGI。能力強化の必要XPは上昇していく。
- 攻撃・回復などのスキル、状態異常を防ぐ装備、HP/SP回復や状態異常治療のアイテムがある。
- 記事はスキルのレベル制限がないと説明している。ただし前提スキルの有無を確定する情報ではない。
- 敗北時のコイン減少があるとの記述。

[meetiによるIIIのプレイ記事](https://i.meet-i.com/?p=163637)にはマップ、ショップ、装備、ターン制バトルの撮影画像がある。赤い地点で戦闘、緑でショップ、黄色で会話という構成を確認できる。

IIIの公開スクリーンショットでは味方2人・複数の敵・HP/SP表示・対象選択を目視した。今回の1人用の最小構成へ、そのまま人数や全ルールを持ち込むとは限らない。

## 原作仕様として断定しないこと

- 分岐型スキルツリーの具体的な構造・前提条件・段数。
- 全スキルの名称、倍率、SP消費量、クールダウン。
- 命中・回避・ダメージ・状態異常の計算式。
- 自動レベルアップと能力ポイントの配布。公開説明の核はXPの直接投資であり、先行試作の方式とは異なる。
- 敵を必ず3体倒すとボス、という固定数。3戦＋ボスは今回のコンパクトな構成の案。
- 焚き火による手動の無料全回復、装備の自動装着、敗北ペナルティなし。これらは先行試作で独自に入れたもの。**焚き火は後述の再確認で削除した。**

## 今回の要件として確定していること

ユーザーの指示を原作への忠実さより優先する。

1. TypeScriptで可搬性を持たせる。
2. マップ上の移動操作はなく、1画面を拠点に戦う。
3. 複数の通常戦をクリアし、ボス撃破でステージクリア。
4. 戦闘報酬によるステータス配分・装備購入。
5. **スキルツリーを必須とする。** 原作での詳細が不明でも今回の要件から外さない。
6. GitHubにpublicリポジトリを作成して開発。

## IIから育成・編成について得られる補足

- IIは塔の各階で敵・階段・イベントを扱う構造で、階移動時の敵復活も英語説明にある。この移動・探索部分は今回の「移動なし」という要件に置き換える。
- [IIの日本語説明（APPLION保存）](https://applion.jp/ipad/app/625279182/)でも、5能力へのXP投資と、習得数とセット数の分離を確認した。
- [IIのプレイヤーによる攻略記録](https://gamefaqs.gamespot.com/boards/714700-stickman-rpg-ii/67941751)には、同じ攻撃スキルを3枠に置き回復を1枠にする編成、SP効率、速度補助、状態異常耐性を組み合わせた攻略例がある。これは個人の実戦報告であり、正確なバランス値の根拠にはしない。
- このことから、今回も「技を覚える」だけでなく「4枠をどう編成して回すか」を育成の中心とする。

## 先行試作から修正する設計案

以下は原作の再現と断定せず、今回の設計案として扱う。

- 成長を「自動レベルアップで能力ポイント」から、**手持ちXPを能力強化とスキル習得に直接使う方式**へ変更。
- 能力はHP / SP / ATK / DEF / AGIを基礎にする。レベルは必要なら累計獲得XPに応じた目安表示とし、投資用XPと分離。
- スキルは攻撃・防御・回復支援の枝を持たせ、前提ノード・消費XP・習得可否・効果を明示。
- **習得済みスキルと、戦闘に持ち込む4枠を分離**。初期から固定の大技を使える方式を廃止。
- 発動にはSPとスキルごとのクールダウンを使う。回復や補助もターンを消費。
- 通常戦の周回でXPを稼ぎ、能力を先に伸ばすか新しい技を取るかを選べるようにする。
- 購入済み装備の所持と装着を分ける。耐性などに意味を持たせる場合は単純な上位互換だけにしない。
- ルールはDOM・保存・描画から独立させ、前提条件、XP消費、セット枠、SP、クールダウンをテストする。

調査前の最初の実装は実験として扱い、現在はXP直接投資・5能力・12技の分岐ツリー・4枠編成・SP・枠ごとのクールダウンを実装した。原作の装備の手動装着・複数消耗品の4枠管理・逃走・状態異常・階層移動は初版に含めず、装備は上位品を購入すると自動で装着し、消耗品はポーション1種類とする。

- Node.jsテスト11件: XPの共用、前提条件、4枠・重複編成、SP・クールダウン、回復・障壁・闘気、地点進行、ボス予告と敗北復帰、購入制約、セーブ検証、獲得資源のみで4ステージの通し攻略、通常戦・ボス・敗北後のHP/SP自動回復とセーブ再開。

## 回復仕様の再確認（2026-11-12）

先行版は、裏付けのない焚き火による無料の手動回復を追加し、通常戦の勝利後にもHP/SPを持ち越していた。これは今回目指す原作リスペクトの仕様から外れていた。

- 公開資料で確認できたこと: [.Appsの初代プレイ記事](https://dotapps.jp/static/articles/qqfs7fmfjbn4pnqf)にはSPがステージ終了後に全回復するとある。HPについて同じ挙動を直接裏付ける記述までは今回も確保できなかった。
- **ユーザーによる原作の補足: 「戦闘が終わるとHPも全回復する」。** この指示を今回の要件として採用する。公開資料のみでHPまで検証済みとは表現しない。
- 現行版: 各戦闘の終了時にHP/SPを全回復し、焚き火・休憩ボタンを削除。回復スキル・ポーションの用途は戦闘中の維持。
- 敗北後の全回復・資源ペナルティなし、中断セーブからのマップ復帰時の全回復は、再挑戦を詰まらせないための本作の仕様として明記する。これらの全挙動が原作と一致すると断定しない。
