# 原作を基準にした再現方針

目的は、ユーザーが挙げたGoro SatoのStickman RPGに近い遊びを、まず成立させること。その後に改善する。参照作品の把握が不十分なまま、独自の戦闘案を正解として実装しない。

参照範囲は従来どおり、マップと1人パーティをIに寄せ、システムはII・IIIも参考にする。今回のユーザー要件である移動なし・固定マップ・スキルツリー・TypeScript・スマートフォンUIは維持する。

## 方針の訂正

- 先の3つの育成方針や独自の敵・反撃案は保留。原作との同等性を確認する前に採用しない。
- 上位互換の装備や攻撃技、周回での育成、分かりやすい数値の成長を、存在するだけで悪い設計と決めつけない。これらが参照作品の成長の楽しさを支えている可能性を調べる。
- 「どの育成方針も均等に強い」を原作にない達成条件として押し付けない。
- 機能が揃うこと、シミュレーションでクリアできること、参照作品に近い体験になることを別々に評価する。

## 再現する対象と、まだ埋めてはいけない部分

詳細な出典と限界は [reference-research.md](reference-research.md) に記録する。

| 対象 | 基準にする内容 | 追加確認すること |
| --- | --- | --- |
| 成長 | XPを能力強化とスキル習得に使う | 各能力の実際の効き方、費用の増え方、序盤の成長速度 |
| 編成 | 習得とセットを分離し、4枠に制限。同じ技の複数セットも扱う | 重複セットが有効な理由、枠ごとの待機・SPとの関係 |
| スキル | 攻撃・回復・補助・状態異常が実戦でどう使われるかを再現の対象にする | 実在する技の効果、対象、消費SP、待機、敵との組み合わせ |
| スキルツリー | 今回の必須要件。ただし独自の前提条件を増やす前に原作の習得構造を調べる | 原作が一覧購入型か前提接続型か、段階や習得条件 |
| 戦闘 | 公開された初代記事では通常攻撃・スキル・アイテム・逃走 | 行動順、敵数、対象選択、状態異常、敵固有の行動 |
| 回復 | ユーザー補足に従い、戦闘終了時にHP/SP全回復 | 公開資料でのHPの直接的な裏付けは未確保と明記する |
| 敵と成長の関係 | 敵に合わせて育成・装備・技を見直す流れを調べる | 敵の固さ、火力、耐性、行動と、それに使われる対処 |
| 装備・消耗品 | コインで購入し、編成して使う | 原作で持ち替えや耐性、消耗品4枠が持つ実際の役割 |
| 周回 | クリア済みの戦闘へ再挑戦して稼げる | 稼ぐ時間と報酬、強化で攻略が楽になる感触 |

未確認の倍率・計算式・技名・敵の数値を、原作の値として記入しない。仮の値が必要な場合は、再現確認前の代用品と明記する。

## まず比較できる基準版を作る

1. 初代の序盤から、実際の敵・技・強化の関係が観察できる短い区間を調査単位にする。説明文だけでなく、プレイ記録・画面・攻略時の具体的な編成を照合する。
2. その区間について、入手XP・お金、能力の購入、習得と4枠編成、戦闘、報酬、次の強化までを記録する。
3. 必要な仕組みを同じ区間で再現する。独自の職業・追加ゲージ・固定周期の大技・汎用防御を、欠けた原作情報の代わりに挿入しない。
4. 通常攻撃で進める範囲、技を覚えた変化、育成が必要になる地点、編成を変えた結果を並べて比較する。
5. 原作に近い遊びになっていることをプレイで確認してから、改善候補を別の変更として試す。

「同等の面白さ」は、原作の機能一覧を実装しただけでは確認済みにしない。育成の手応え、技を覚える価値、4枠を考える理由、周回と突破のテンポも比較対象に含める。

## 参照する設計理論と使い道

理論を原作の代用品にはしない。観察結果を理解し、再現版を評価する補助として用いる。

### MDA

[Hunicke・LeBlanc・Zubek, MDA: A Formal Approach to Game Design and Game Research](https://www.cs.northwestern.edu/~hunicke/pubs/MDA.pdf)

ルール、そこから生じるプレイ中の振る舞い、プレイヤーの体験を分けて捉える。今回なら「4枠」「XP消費」があるだけで再現完了にせず、それが編成の工夫や成長の手応えへつながっているかを見るために使う。

### 費用と効果の関係

[Game Balance Concepts — Level 3: Transitive Mechanics and Cost Curves](https://gamebalanceconcepts.wordpress.com/2010/07/21/level-3-transitive-mechanics-and-cost-curves/)

強いものほど費用が高い成長構造と、相性による強弱を区別する。上位装備や上位技を一律に否定せず、効果に対してXP・コイン・SP・行動・編成枠などの負担がどう関係しているかを整理する。

## 改善を試すとき

- 比較用の基準版を残す。
- 一度に変えるルールを絞る。
- 何を改善したいかと、維持したい原作の良さを先に書く。
- 成長の楽しさや編成の意味、短時間の遊びやすさが弱くなった場合は採用しない。

現段階では再現区間の十分な観察が済んでいない。独自案を具体化することより、この確認を優先する。
